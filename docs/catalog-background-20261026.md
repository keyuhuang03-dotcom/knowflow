# 教材目录后台识别修复（2026-10-26）

旧流程把最多六页图片放在一次长 HTTP 请求中，识别预览仅回传到当前浏览器组件，确认保存是独立操作。页面刷新、导航或长请求失败可能导致结果不可见。线上只读检查时，408 仅有未分区旧节点，具体分区未保存新目录；未找到能确认某次旧请求失败原因的日志。

新流程：上传图片 → 建立 SQLite CatalogJob → 现有单 Worker 逐页识别并持久化 → 页面自动恢复进度/预览 → 核对保存范围 → 确认入库。识别任务不会直接修改教材结构。保存目录与标记任务已保存在同一事务中完成。

- 复用单 Worker 和全局数据库租约，错题任务优先；不增加服务。
- 每次识别一页，并携带上页目录层级，保持跨页章节衔接。每页最多三次尝试，已完成页不重新识别。
- 有限重试、过期租约恢复、页级检查点；失败后可继续，或放弃任务重新选图。放弃不删除已保存教材或照片。
- GET 状态接口按学科部分恢复最新任务；结果明确标为“识别完成·尚未保存目录”。
- 本地校对草稿仍保留；后续页完成时不会用部分旧草稿覆盖完整新结果。
- 跨页合并容量提升到600条，仍保留页码冲突和输出截断检查。超容量会提示，不静默保存缺失目录。
- 新迁移仅增加 CatalogJob 表和索引。旧模型及历史关联不删除。

验证：40 项隔离测试通过；独立进程恢复、第二页服务失败后仅重试第二页、重复提交、分区隔离、取消任务与确认入库均覆盖。Chrome 手机/桌面检查覆盖部分结果刷新、完整预览恢复、确认替换、目录逐级展开和历史笔记保留。备份副本迁移演练通过，16张旧表数量不变；类型检查、构建通过；lint零错误、3项既有警告。

限制：模拟服务验证不证明真实模型识别准确率或耗时。逐页处理主要减少单次长请求并提供可靠进度，不能保证整本总耗时降低。旧同步请求没有服务器任务记录，不能自动找回其未返回结果；旧照片/本地草稿保留时可重新发起识别。Safari实机未验证。
