## 1. 一页了解项目

KnowFlow 是用于个人考研学习的知识工作台。以教材目录建立知识骨架，把错题、笔记和复习记录关联到已有知识点。当前已经上线，属于**单人使用的 MVP**，不是公开注册、多用户隔离的产品。

当前主链路：

- 手机拍照或选择多页图片，处理图片后上传；照片、错题记录和任务先保存。
- 独立后台 Worker 识别题干、生成标准解答及已有知识点推荐；保存成功后可以退出页面。
- 用户自己填写卡点，勾选或自填错因；AI 不推断用户究竟错在哪里。
- 教材目录支持多页后台识别、章节树和页码预览，用户确认后才写入知识库。
- 手机优先快速录入和查看状态；桌面保留图谱、教材管理、学习分析和深度复盘。

## 4. 我们交互中确定的产品原则

### 4.1 用户明确要求

1. **先保存，再整理。** 拍照后不要让用户长时间等完整 AI 分析才能保存；已有记录和照片不能因识别失败丢失。
2. **AI 给标准解答，不猜学生的错误。** 用户会自己写卡点；AI 不必看懂用户手写步骤后才给出答案。错因可以给中性的自查选项，但不能将建议断言成用户事实。
3. **目录要真实且有层次。** 标题、页码、章/节/小标题和跨页归属都重要。总览先看章，展开再看小标题；页码直接显示“第 N 页”，不要重新加“首项”字样；不能只识别几个泛化学科名。
4. **错题和目录都需要多页。** 不能把多图支持只做在其中一个入口。
5. **减少冗余。** 复习卡片不能堆叠重复的“待补充”“无法判断”“Skill 完整诊断”；方法、步骤和答案要清楚分层。
6. **全场景正确渲染数学。** 标题、选项、摘要、提示和解答都可能包含公式，不能只处理正文，留下 `$...$` 或 LaTeX 原文。
7. **移动与桌面差异化。** 手机快速录入与看状态；桌面承担图谱、管理、分析和深度复盘。移动优化以 768px 为边界，不能顺带破坏桌面。教材管理入口应放在添加错题下方，与学科分区标签留足间距，不挤成一团。
8. **保留视觉语言。** 奶白、青柠绿、Liquid Glass、柔和手绘和克制留白；提高信息密度不等于改成传统后台表格。
9. **交互要直接。** 裁剪是拖照片边框，不是拉进度条；四个导航项统一，只高亮当前项；保存必须有明确反馈。
10. **按钮按用户理解工作。** 填了错因后点“保存补充”也应该保留错因，不要求用户记住多套互不相通的保存逻辑。

### 4.2 需要长期遵守的协作方式

- “继续”“按优先级修复”意味着继续完成实施、验证及已授权的后续工作，不只回复可以或给建议。
- 先检查现有实现，再做最小必要修改；不推倒重写，不替换成熟结构。
- 保留学习数据、照片、历史记录、用户修改与关联。不要为了让目录看起来干净直接删库或删旧节点。
- 用户不希望反复确认已授权的事情。云平台与密钥配置应给出明确操作，不假设用户熟悉运维术语；使用清楚的中文，实际完成可执行部分再报告。
- 新行为若确实需要缺失信息，应提出具体问题；不能将普通实现选择变成重复审批。
- 不要要求用户粘贴 API 密钥、密码或私钥；使用已授权的本地配置和 SSH，避免把秘密写入日志、文档或 Git。
- 有逻辑风险的修改先在隔离数据中测试，不能拿生产学习记录做写入测试。
- 报告实际结果，区分“代码实现”“本地验证”“GitHub 已同步”“线上已发布”“未验证”，这些状态不能互相替代。
- 用户要求截图时提供真实运行截图。桌面保留现状的要求要通过对照检查，而不是口头承诺。

## 6. 架构与代码入口

cd /Users/huangkeyu/kaoyan-workbench/app
