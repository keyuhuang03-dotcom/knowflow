## 实现文件与接口

| 文件 | 作用 |
| --- | --- |
| `app/prisma/schema.prisma`、新迁移 | 未知科目、持久任务和全局 Worker 租约 |
| `app/src/lib/mistake-service.ts` | 复用原保存逻辑；新增 capture 保存，允许零节点，不要求教材/分析确认 |
| `app/src/app/api/upload/route.ts` | capture 上传在响应成功前，保存错题与任务；稳定 UUID + 文件内容哈希避免相同重试重复 |
| `app/src/lib/mistake-queue.ts` | 任务领取、租约续期、有限重试、恢复、AI 结果与版本校验 |
| `app/scripts/mistake-worker.ts` | 独立单 Worker 进程，加载现有 `.env`，支持退出与一次处理 |
| `/api/mistakes/[id]/processing` | 无缓存状态查询和幂等的手动重试 |
| `MistakeWizard`、`ImageIntake`、`ProcessingStatus` | 拍照上传、保存状态、结果回看；复用图片处理和草稿 |
| `LegacyMistakeWizard` | 保留原手动分析、选择与确认流程 |
| 错题详情与列表、首页、Skill 读取 | 兼容未知科目，显示整理状态，零关联可编辑保存 |
| 图谱 API | 读取旧主节点和多关联并去重，不重设计图谱 |
| 备份 API | v2 保存多知识点关系及任务，导入兼容 v1，失败事务回滚 |
| `compose.yaml` | web 与 Worker 使用同一镜像、SQLite 和上传目录，不引入外部队列 |

默认录入将 `capture` 元数据与图片一起提交；只有照片、错题和任务都持久化后才显示“照片已保存”。上传前可选择科目、简短卡点、同图过程或单独过程图，也可全部留空。旧草稿中的已上传原图可直接保存并整理。

## 队列行为

- 单 Worker，每次只处理一个任务；数据库全局租约防止误开第二个进程。
- 默认租约 90 秒，运行时每 30 秒续期。崩溃后其他 Worker 等待租约过期并重新领取。
- 每条任务最多 3 次尝试；瞬时失败按 5 秒、10 秒退避。第三次失败后停止自动尝试。
- 未配置 AI 或图片不可读取时立即显示失败，保留记录；配置/修复后手动重试开启一轮新的有限尝试。
- 模糊识别归档为待补充，不自动循环重试，不编造题干和错因。
- 只匹配已有教材节点；未知科目的匹配若跨多个科目则不自动关联。零匹配仍保存，不创建教材节点。
- 用户已明确选择的关联不被 AI 替换；AI 自动关联在详情中可修改或清空。
- 用户编辑分析会取消旧任务；补充过程/科目且不手动提交分析时重新排队。旧输入版本的结果不可覆盖用户修改。
- 关闭浏览器不会终止 Worker；关闭运行 Worker 的终端会停止处理，任务保留，重启后恢复。
- 没有自动删除照片、孤立文件、历史记录或 Skill 原件。

## 本地运行与验收

迁移应先备份并停写。已有本地数据不运行 seed、不使用 migrate reset。需要迁移时，在应用目录执行 `npx prisma migrate deploy`；本轮已在停写备份后应用本地迁移，逐表核对全部旧字段和关系不变，完整性与外键检查通过。

在项目根目录分别运行两个终端：

```sh
npm --prefix app run dev
npm --prefix app run worker
```

Worker 使用现有 `DATABASE_URL`、`UPLOAD_ROOT` 和 `MISTAKE_AI_*` 配置，无新密钥或 AI 服务。web 和 Worker 必须使用同一个数据库及上传目录。数据库存在只说明任务已登记，不意味着 Worker 正在运行。

1. 打开 `/wrong-questions/new`，相册或拍照选图；可选旋转/裁剪后点击上传。
2. 等待“照片已保存”后关闭页面，在错题列表中重新进入，检查整理状态。
3. 未配置 AI 时检查照片仍可打开、记录仍可编辑；配置后点击“重新整理”。
4. 连续重试同一次上传应只有一条错题、一条任务；新拍一道使用新的记录 ID。
5. 停止 Worker 后提交，状态保持等待；重启后继续处理。强制终止正在处理的进程时，默认最多等待 90 秒租约恢复。
6. 检查旧错题、旧主节点、多关联、笔记和 Skill 历史仍可查看。
7. 真机 Safari 单独检查相机权限、方向、公式清晰度、裁剪、后台切换和存储受限情况。

## 备份兼容与服务器更新

- JSON 备份升级 v2，包含错题全部关联、新增状态和任务；导出使用数据库事务快照。
- 导入前停止 Worker；运行中的租约存在时拒绝导入。历史 v1 只能恢复其实际包含的旧主节点，无法凭空恢复当时未导出的额外关系。
- 任务导入时清除进程租约，把处理中任务恢复为待处理；Worker 全局租约不作为永久数据恢复。
- JSON 仍不包含图片与 Skill 原始文件；完整恢复继续使用数据库、上传目录和 Skill 数据包。
- 本轮只准备 Compose 修改，未执行服务器命令。服务器更新前 `docker compose stop web worker`，同时备份数据与配置，再手动更新代码与启动。
- `docker compose up -d --build` 构建共享镜像并启动 web/worker；检查 `docker compose ps` 和 `docker compose logs --tail=100 web worker`。默认 Worker 等待 web 的迁移可用后处理。
- 不能只启动 web 就认为后台整理可用。云端 Docker/Compose、资源占用、真实 AI、HTTPS 和迁移需要部署阶段实际验收。

## 2026-10-09：真实数学照片回归与识别修正

接口连通测试不能证明复杂数学识别质量。手机实测暴露了倒置多题照片、积分上下限和指数范围误读、同图手写过程被忽略，以及未排版的 LaTeX。

### 修改范围

- `mistake-ai.ts`：先独立识别印刷题干与同图手写证据，再以识别结果生成简短卡片；分析阶段不能改写题干。单题倒置时尝试在内存中转正，原照片不变。多题、未可靠转正、关键符号不清时不继续诊断。DeepSeek 请求关闭思考模式、限制输出，单次请求 20 秒、整轮 API 请求共用 30 秒取消信号。
- `mistake-recognition.ts`：验证题目数量、方向、关键条件和模型不确定提示；不接受“模型说 clear”作为唯一条件。
- `mistake-contract.ts`：JSON 中兼容新增 `recognizedWork`、`cardPending`，历史记录可继续读取，无数据库迁移。
- `mistake-queue.ts`：题干成功但卡片生成失败时保留识别内容，显示待补充而非丢掉识别结果。第一次识别请求失败仍走原有有限重试；30 秒是单轮上限，不是整条任务含重试的总上限。
- `MathText`、`ReviewCard`、`AnalysisFields`：使用 KaTeX 转换带分隔符的公式为原生 MathML；保留文字，非法公式降级成文本，禁用不可信 HTML/链接。默认展示题干，提示折叠；题干不清不展开可靠解法。历史未带公式分隔符的文本保留原样，可重新整理生成新版。
- `ProcessingStatus`、`MistakeDetail`：已完成的 AI 记录也可重新整理；不会批量覆盖已有记录、个人补充或原照片。
- 新增 KaTeX 依赖；sharp 是 Next.js 已安装的依赖，现显式声明用于后台方向校正。不增加新模型服务、基础设施或数据库迁移。

### 实测与限制

- 第7题单题照片：正确读取 `d/dx ∫₀ˣ cos²(x-t)dt`，自动识别同图换元步骤与旁注；成功样本约 3.6–3.7 秒。
- 第6题的正向单题裁剪副本：正确读取下限 `1`、上限 `e^x+1`（不是 `e^(x+1)`），成功样本约 3.1 秒。此副本只用于测试，没有替换上传原文件。
- 倒置整页多题图片：模型仍曾误读上下限和旋转角度，也发生过不合法响应。不能承诺整页可靠识别；现在保留原图、提示转正裁剪，并阻止多题继续诊断。
- 真接口重复请求中还出现长等待/失败。上述耗时仅为成功样本，不是性能保证；新增超时与题干保留保护。
- 21 项自动化测试通过，含卡片生成失败保留题干、历史兼容、重启恢复和安全公式显示；类型检查与构建通过，lint 无错误、3 项已有警告。
- 手机尺寸无界面 Chrome 截图已确认公式显示和布局；实际 iPhone Safari 显示仍需用户验收。没有把模拟接口测试作为真实数学识别质量结论。
