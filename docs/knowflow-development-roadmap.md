# 知序 KnowFlow 产品定位与开发路线图

> 日期：2026-10-09
> 状态：基于当前本地代码、数据库结构与 Skill 的开发方案，尚未实施本路线图。
> 推荐第一阶段：拍照后可靠保存 → 后台自动整理 → 自动关联已有知识点 → 复习卡片 → 事后纠错。

## 1. 产品定位与边界

知序 KnowFlow 是 AI 驱动的个人学习知识库，目标是最大程度减少用户整理错题、笔记和知识点的时间，让用户专注于学习。

以教材为骨架，以学习记录为内容，由 AI 理解、整理和关联，逐步构建个人知识体系。

- 用户负责学习和拍照，AI 负责整理；文字、来源、标题与分类尽量非必填。
- 拍照后先可靠保存，再自动整理；低置信度、无匹配节点、AI 不可用均不阻止归档。
- 只有必要时追问；用户可以跳过，并在之后用一句话补充卡点。
- 题目图片不能证明个人错因；看不清的条件和未展示的步骤不得补造。
- 一条错题、笔记或个人方法可以关联多个已有知识节点。
- AI 不自动修改教材目录；新增、移动、合并、重命名等重要结构变更需要用户确认。
- 图谱服务于检索与复习，不将每道错题变成图谱节点。
- Obsidian 为可选工具，第一阶段只做单向 Markdown 导出，不开发双向同步或插件。

## 4. 新定位与现有实现的差距

| 新定位 | 当前差距 | 修改方向 |
| --- | --- | --- |
| 用户拍照，AI 整理 | 上传、分析、校对、选择节点、确认保存分成多个步骤 | 单页快速提交，后台处理 |
| 信息不足也能保存 | 保存要求已确认主教材和 1～3 个节点 | 支持零关联、未知科目、待整理记录 |
| 自动保存 | 分析前主要依赖浏览器草稿 | 上传成功即建立服务器记录 |
| 杂乱手写不阻塞 | 完整 Skill 诊断要求真实步骤 | 基础归档与完整诊断分层 |
| 用户事后纠错 | Skill 归档后部分过程和关联不能直接修改 | 统一纠错入口与修订适配 |
| 图谱体现全部关联 | 图谱 API 只读旧单主节点关系 | 与节点详情统一多关联查询 |
| 教材骨架稳定 | 图谱已有 AI 提取、新建知识点入口 | 隔离结构修改，保留用户确认 |
| 可持续使用 | JSON 备份漏错题多节点关联，不含图片和 Skill 原件 | 补齐可恢复备份 |
| Obsidian 可选 | Skill Markdown 不等于完整知识库导出 | 带稳定节点链接和附件的导出包 |

另外需要修正两个表达和行为：

1. 当前上传的是裁剪、压缩后的图片，不能承诺保存了未经处理的原始照片。
2. 图谱将“有关联错题”转换为弱连接，容易被理解为“知识点薄弱”；应改为中性的关联数量提示。

## 5. 推荐整体技术架构

保留单体应用，补充轻量后台任务机制：

```text
手机 / 桌面
    ↓
Next.js 页面与 API
    ↓
先保存记录、附件和任务
    ├─ Prisma + SQLite：业务记录、状态、知识关联、任务
    ├─ 文件系统：原始图片、分析用处理图片
    └─ 后台处理进程
         ↓
       视觉模型 → 结构校验 → 已有节点匹配 → 复习卡片
         ↓
       按条件调用 Mistake Learning Skill
```

- SQLite 适合当前单人规模，暂不换数据库。
- 新增数据库任务表，由同一项目的后台进程轮询；服务器初期并发为 1。
- 任务具有租约、超时、有限重试和重启恢复；不依赖浏览器一直打开。
- 不使用 HTTP 响应后无保障的异步调用承接长任务。
- 浏览器先轮询任务状态，暂不引入 WebSocket。
- 暂不增加 Redis、独立 OCR 服务、向量数据库或微服务。
- 保持现有视觉风格、GlassCard、共享导航、表单和复习组件。

图片识别先使用已有视觉模型接口。是否需要独立 OCR 或更复杂检索，由真实样本评估决定。

## 6. 数据库增量调整

### 6.1 保留现有模型

- `Subject → Chapter / KnowledgeNode`：教材骨架。
- `MistakeItem`：错题业务记录。
- `Note`：笔记与个人方法。
- `KnowledgeNodeRelation`：知识点间关联。
- `StudySession`：学习时长记录。

暂不将现有业务模型重构为统一“学习记录大表”。

### 6.2 P0 必要字段和模型

| 调整 | 目的 |
| --- | --- |
| 错题允许未知科目 | 科目识别失败仍可保存，不创建虚假占位科目 |
| 整理状态、更新时间、版本号 | 区分待处理、处理中、完成、失败，避免旧 AI 结果覆盖用户修改 |
| 后台任务表 | 保存任务类型、目标记录、输入版本、租约、重试次数、错误与时间 |
| 附件记录 | 表达原题、过程、原始版本、处理版本及拍摄顺序 |
| 分析 JSON 新版本 | 保存识别状态、证据、缺失信息、模型版本和关联依据 |

“处理是否完成”与“信息是否充分”分开：整理已完成的记录仍可以是错因待补充。旧记录的分析 JSON、图片 URL 和字段继续兼容读取。

### 6.3 多知识点关联

现有隐式多对多已解决数量问题，不需重做。但自动关联需要保存每条关系的来源、理由与用户纠正状态，建议增量增加显式关联模型：

```text
mistakeId、nodeId
来源：AI / 用户 / 历史迁移
状态：自动关联 / 用户确认 / 用户移除
匹配理由、关联时间、分析版本
唯一约束：mistakeId + nodeId
```

迁移和兼容步骤：

1. 回填现有 `linkedNodes`。
2. 补入未出现在多关联表中的旧主节点，去重。
3. 历史关系标为历史迁移，不能伪装为用户确认。
4. 过渡期通过统一事务维护兼容关系，禁止多个独立写入入口。
5. 所有读取切换并验证后，再决定是否移除旧字段。
6. 保存允许零节点；默认展示最相关的少量节点，不凑数量。

关联确认和个人错因确认分开。自动关联不意味着个人错因已经确认。

第一阶段继续保留 `Subject.textbookTitle`。需要换教材、版本管理或多教材并存时，再引入 `Textbook` 实体。

## 7. Mistake Learning Skill 集成

原始 Skill 入口为本机 `错题整理skill/skills/mistake-learning/SKILL.md`。项目适配入口为 `app/src/lib/mistake-skill.ts`。

| 能力 | 实际承担者 |
| --- | --- |
| 图片和手写识别 | 视觉模型 |
| 语义诊断 | 模型提示词和适配器 |
| Schema 与逐字证据校验 | Skill Python 脚本 |
| 不可变诊断和追加修订 | Skill |
| 教材骨架和应用关联 | Prisma |
| Markdown 诊断卡、复习卡 | Skill 投影脚本 |
| 完整网站导出 | 待开发 |

现有适配器使用 `validate`、`save`、`effective`、`catalog`、`apply-event`。原始 Skill 自身不调用视觉模型，不是独立 OCR 引擎。

### 两层集成

1. **基础整理层**：任何图片都能归档；识别失败时保留原图与待补充状态。
2. **证据诊断层**：存在可辨认的真实步骤时生成完整 Skill 诊断；失败不撤销基础记录。

Skill 支持部分缺失的 `needs_information`，但现有 Schema 和适配器不适合直接承接完全没有过程的记录。不能补造步骤以通过校验。

进一步实施要求：

- 让基础分析和完整诊断共享结构化识别结果，减少重复 OCR、费用和结论冲突。
- Prisma 负责业务记录与教材关联；Skill 负责诊断证据和修订，不形成两套竞争教材目录。
- 用户纠正通过适配器协调应用结果与 Skill revision。
- Word 改为按需导出，不阻塞手机整理流程。
- Skill 掌握分数暂不自动写入 `KnowledgeNode.masteryLevel`。
- V2/V2.5 历史纠正辅助等能力放在后续评估，不因为原始 Skill 存在便宣称项目已完整接入。

逐字证据校验只能证明引用与识别文本一致，不能证明 OCR 文本忠实于照片；真实样本评估和原图核对入口必须保留。

## 8. AI 识别、分析与归档技术流程

1. **拍照或连续选图**：默认方向处理和压缩；裁剪、旋转作为可选编辑。标题、来源、过程文字均非必填。
2. **先保存输入**：保存原始图片和处理图片。使用稳定记录 ID；上传完成即创建待整理记录，显示“已保存，正在整理”。
3. **创建持久任务**：用户可离开页面，重新进入仍可查看进度。
4. **识别可辨内容**：区分题目、真实步骤和用户短补充，保留缺失项，不补齐未写出的推导。
5. **结构化分析**：保存识别状态、证据引用、可能卡点、方法和待补充项；没有过程时错因保持未知。
6. **匹配已有节点**：优先当前科目和教材路径，只允许数据库已有 ID。可靠匹配自动关联，歧义结果保留候选，记录已保存。
7. **生成复习卡片**：复用卡点、特征到方法、下次检查；未知内容明确待补充，详细分析折叠。
8. **条件式 Skill 归档**：基础结果和完整诊断分别显示状态，Skill 失败不丢失基础结果。
9. **事后纠错**：支持一句话补充、移除错误关联、校对题干、补拍，按需重新处理。
10. **版本保护**：用户修改后增加版本，后台结果只有输入版本一致才可应用。

初期置信度使用“清楚、部分可辨、无法判断”等可解释状态。模型自报百分比不能直接当成已校准的准确率。自动关联阈值须通过真实样本确定，不预先承诺识别准确率。

## 9. 简化知识图谱

继续使用 vis-network，修改数据和交互，不更换图库。

- 桌面首页默认展示学科和核心章节，点击后逐级展开。
- 选中知识点时打开关联错题、笔记、方法和学习状态面板。
- 教材层级使用稳定树形布局；知识关联只在选中节点附近按需显示。
- 拖动只影响视觉位置，不修改教材父子关系。
- 错题和笔记显示数量和详情列表，不变成图谱节点。
- 手机默认目录列表、拍照与复习入口，图谱作为可选视图。
- 稳定后关闭持续物理模拟，减少抖动和耗电。
- 首先修复多关联遗漏；随后增加按层级请求，避免一次加载全部节点和关联内容。

`Subject`、`Chapter` 可以生成展示节点；`KnowledgeNode.parentId` 表达教材层级，`KnowledgeNodeRelation` 表达非层级关联，两者不能混用。AI 对教材结构变更形成建议，用户确认后执行。第一阶段只自动维护内容关联。

## 10. Markdown / Obsidian 导出

新增单向 ZIP 导出：

```text
KnowFlow/
  知识节点/
  错题/
  复习卡片/
  笔记/
  attachments/
  manifest.json
```

- 文件名使用可读标题加稳定 ID，避免重名。
- 使用 Obsidian 内部链接，例如 `[[极限--节点ID]]`。
- 一道错题链接多个知识节点，节点文件列出关联记录。
- 图片复制到附件目录，不使用只有网站才能访问的上传 URL。
- 元数据保留原始 ID、教材路径、状态、时间和分析版本。
- 未确认错因在正文明确标注，不能通过导出变成确定事实。
- 可复用 Skill Markdown 内容，但关联以应用稳定节点 ID 为准。
- 使用一致的数据快照；图片缺失明确报告，禁止静默导出不完整包。
- 不开发双向同步和插件；导出不修改源数据。

Markdown 是知识浏览产物，不能替代 SQLite、附件和 Skill 原始记录的可恢复备份。

## 12. 分阶段开发与验收

| 阶段 | 范围 | 验收标准 |
| --- | --- | --- |
| A：兼容性与真实样本基线 | 新状态契约、迁移方案、关联和备份副本验证、经授权的真实手写样本 | 旧记录可读；关系无丢失；备份可恢复；记录真实识别错误类型 |
| B：自动归档基础 | 单页拍照、附件、零关联记录、任务表、后台进程、重试 | 上传后可离开；刷新和进程重启不丢任务；重复提交只有一条记录；AI 不可用也保存 |
| C：自动整理与纠错 | 视觉识别、节点匹配、卡片、短补充、版本保护、条件式 Skill | 不编造模糊步骤；关联 ID 均存在；零匹配不阻塞；用户修改不被旧结果覆盖；诊断失败不丢原图 |
| D：图谱与检索 | 分层首页、详情、多关联一致性、手机列表 | 默认数量受控；逐级展开稳定；全部关联节点可查看同一错题；手机触控无明显冲突 |
| E：笔记与导出 | AI 整理笔记、关联、Markdown ZIP | Obsidian 可打开；内部链接可跳转；图片显示；多关联和待补充状态保留；源数据不变 |

阶段按交付物推进，不用固定日期代替验收。阶段 A～C 是推荐首期范围；阶段 D/E 在归档闭环可靠后启动。

真实样本基线建议覆盖至少 30～50 个不同情况：清晰题目、模糊小字、杂乱步骤、只有原题、错误科目候选、多知识点、无匹配节点。该数字是建议验收样本量，当前尚未完成。

### 每阶段检查

- 运行适用的 lint、typecheck、测试与生产构建。
- 使用隔离数据库和临时附件目录测试写入与迁移。
- 对任务增加断网、响应丢失、进程终止、重复提交、用户编辑竞态测试。
- 对迁移和导出检查关系集合，不能只检查记录数量。
- 对真实 AI 与 iPhone Safari 单独记录结果；模拟测试不标记为真机或模型质量通过。

## 13. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 手写、公式识别错误 | 原图、部分结果、未知项、真实样本评估；不强制完整识别 |
| 后台任务丢失或重复 | 持久任务、租约、稳定 ID、有限重试、重启恢复 |
| 旧 AI 结果覆盖用户输入 | 输入版本校验，用户纠正优先 |
| SQLite 与 Skill 文件无法跨存储原子提交 | 分阶段状态、attempt_key 去重、对账和恢复 |
| 迁移或备份漏关联 | 数据副本验收，校验关系集合及附件恢复 |
| Safari 内存和后台回收 | 限制处理尺寸、释放资源、服务端任务、真机验证 |
| AI 关联错误或目录漂移 | 只用已有 ID，理由可查看，可移除，结构修改需确认 |
| 单人服务器资源限制 | 单任务并发、按需 Word、图谱分层加载；实际容量测试 |

## 14. 第一阶段建议与部署边界

早期第一阶段建议的主链路现已落地；现行交互为：**照片保存 → 后台整理 → 推荐已有节点并由用户确认 → 标准解答卡片 → 用户自填卡点/错因**。不再要求 AI 判断用户手写步骤或错因。

同时修复图谱多关联读取和备份遗漏，暂不重做首页图谱，不引入独立 OCR 或向量数据库，不开发 Obsidian 同步。首期成功标准是：用户拍完可以放心离开，回来能看到可靠的整理结果，AI 无法判断时资料仍完整保存。

网站与备案已完成，Mac 构建与 SSH 发布已使用，更新由获授权维护者按 [部署文档](aliyun-deployment.md) 执行。当前运行版本和验证边界见项目现状；GitHub 提交仍不等于自动上线。
