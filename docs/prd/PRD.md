## 1. 产品定义

KnowFlow 是面向个人考研学习的 Web 工作台，以个人教材目录为知识骨架，将错题照片、AI 整理解答、个人卡点与笔记连接起来，帮助用户在不中断学习的情况下先保存材料，再整理、找回与复习。

一期核心问题：**做题时发现了值得记录的问题，但把照片整理成日后可找回、能复习的记录，还需要转录、查解答、分类和补充个人思考。额外整理步骤可能打断当前学习。**

上述困难是由产品设计与实现反推的需求假设，尚无正式访谈样本或耗时测量支撑其普遍性。项目起点是个人学习工作台，后续逐步收敛至考研错题与知识管理；具体转向时间、原始记录和个人决策过程由用户核对。

### 1.1 核心价值假设

- 先保存照片与任务，再后台整理，可能减少等待对学习的打断。
- 依据个人教材建立目录，可能比独立图片列表更容易定位同类知识记录。
- 将 AI 解答与用户自述分开保存，可能保留更有价值的个人复习线索。

这些是待验证的价值假设，不表述为已降低整理耗时、提高留存或提升成绩。

### 1.2 一期目标与非目标

| 一期目标 | 不纳入一期成果 |
| --- | --- |
| 原题、记录、任务可靠保存 | 公开注册、多用户隔离与团队协作 |
| 支持离页后的 AI 整理和失败恢复 | 保证模型解答正确或自动判断学生真实错因 |
| 按教材目录关联错题与笔记 | 完整全科内置知识库、经验证的全局能力诊断 |
| 找回记录、补充卡点并复习 | AI 组卷、资料提取题集与在线判题 |
| 提供登录、备份及发布保护 | Obsidian 实时同步、原生 App、多端离线同步 |

## 3. MVP 范围与取舍

下表是对已实现方案的产品解释，并非历史排期或原始评分的复原。P0/P1 表示一期价值优先级，与缺陷修复优先级分开理解。

| 能力 | 优先级 | 取舍依据 | 成功边界 |
| --- | --- | --- | --- |
| 照片、记录与任务先保存 | P0 | 任何 AI 能力都不能替代来源可靠落地 | 明确服务器确认后才显示已保存 |
| 后台识别、解答和失败重试 | P0 | 降低等待、离页和中断造成的损失 | 失败保留来源，结果需校对 |
| 教材目录校对与知识关联 | P0 | 建立个人资料的归属与找回路径 | 候选预览不等于正式导入 |
| 用户自填卡点与错因 | P0 | 个人事实不应由模型猜测 | AI 更新不覆盖用户内容 |
| 列表筛选与回看复习 | P0 | 验证记录可以被再次使用 | 能找到、打开并保存复盘 |
| 笔记、任务、时长与每日复盘 | P1 | 辅助学习记录与关联 | 不包装为能力测评 |
| 原有 vis-network 图谱 | P1 | 辅助浏览已有节点与关系 | 不是自动生成的权威知识体系 |
| 组卷、MD 正文与资料练习 | 后续 | 额外引入内容、判题、同步与验证成本 | 本期不交付，二期暂缓 |

关键决策：把“保存完成”和“整理完成”拆开；模型先转录题干再生成解答；教材识别后需人工确认；用户自述单独保护。以上决策有代码依据，但其实际收益仍需测量。

## 4. 信息架构与原型范围

手机一期导航为：首页／知识库／拍照／记录。其中“拍照”进入错题录入，“记录”进入错题列表。桌面保留首页、知识库、错题、学习记录、设置及其他辅助页面入口。

本次原型稿覆盖手机核心链路：S01 首页、S02 错题录入、S03 已保存与后台状态、S04 解答与个人复盘、S05 知识库、S06 教材目录校对、S07 错题列表、S08 整理失败与重试。它是根据一期源码及历史上线截图制作的回溯原型稿；本地提供可点击 HTML 与矢量 SVG，Figma 在线页面因额度限制尚未写入。该稿不代表逐像素复刻今日线上页面。原型中演示题目、数量、教材名称均为示例数据，非真实使用指标。

辅助功能如笔记、学习统计、设置不在本次核心原型页面覆盖范围内，仍属于下列需求说明范围。原型不暗示已完成全站高保真设计。

## 5. 核心端到端流程

### 5.1 错题记录与复习

首页拍下错题 → 相册多选／连续拍照 → 检查顺序、旋转与裁剪 → 可选填写科目和卡点 → 上传全部页面 → 服务器确认照片、记录与任务已保存 → 可离页 → Worker 识别题干并保存检查点 → 生成解答和候选关联 → 用户校对与确认 → 补充个人复盘 → 从列表／知识节点找回 → 再次复习。

异常分支：上传前失败保留浏览器输入并允许重试；上传响应不确定时使用原记录编号重试；识别模糊进入待补充；模型失败显示失败及重试，不删除原照片；后台结果到达时保留最新个人自述。

### 5.2 教材知识目录

首页录目录／知识库添加教材 → 选择学科及部分 → 多页目录上传 → 后台逐页识别 → 查看进度与候选 → 校对书名、层级、页码 → 确认追加或替换 → 从对应分区打开目录 → 通过节点关联错题与笔记。

异常分支：后续页失败保留已完成页；候选不直接污染正式目录；替换旧教材采用归档并保留历史关联。

## 6. 功能需求与验收条件

### FR-01 多页照片保存

- 入口：手机首页、拍照导航及错题页。
- 支持 JPG、PNG、WebP；每批最多 6 页，每页不超过 10MB，总计不超过 24MB。HEIC 需转换。
- 页面支持多选、连续拍摄、逐页旋转、裁剪、排序和移除；客户端压缩最长边到 2400px。
- 科目、卡点、来源和名称可以不填。单独过程照片尚待处理时应阻止不完整提交。
- 未应用裁剪时，先应用或重置再切页／上传。
- 全部文件及记录、任务创建成功后才显示“照片已保存”。浏览器草稿为尽力保护，不承诺换设备或清理存储后恢复。
- 稳定记录编号用于重试，同一编号不得替换为另一批照片。

验收：正常批次顺序保留；超限被拒绝；失败输入可重试；响应丢失重试不产生第二条记录；AI 不可用不影响已保存来源存在。

### FR-02 后台整理与解答

- 独立 Worker 领取持久任务；有限重试、租约及版本检查处理进程中断。
- 题干转录与独立求解分开。模糊或多题输入提示补充，不补造题目条件。
- 保存题干、标准解答、最终答案、方法及已有知识点候选。公式使用数学排版。
- 解答供核对，不保证准确；模型不得将自查选项写成用户已犯错误。
- 识别检查点可供后续解答重试复用；过时输入结果不得覆盖新版内容。

验收：离开页面后任务仍可执行；重启可恢复；旧任务结果不覆盖新输入；模型错误与缺配置有反馈，照片与记录保留。

### FR-03 知识关联与个人复盘

- 用户可确认或修改关联，卡点／错因可空、多选或自填。
- 保存补充、保存错因、完成复习等入口均应保存当前个人草稿。
- 后台整理保留最新 selfReport；已确认关联不应被 AI 建议整体替换。

验收：用户在整理中填写卡点，后台完成后仍保留；保存后重新打开一致；知识节点能找到对应错题。

### FR-04 教材目录导入

- 数学按高数／线代／概率统计，408 按四部分管理；英语、政治独立。
- 按页保留识别进度、条目和警告；ready 仅代表候选可预览。
- 用户确认书名、层级、页码与归属后导入。替换教材归档旧节点，保留旧资料关联。

验收：失败后可继续已完成页；确认前正式目录不变；保存后可找到；替换不删除历史错题与笔记。

### FR-05 记录找回与辅助知识浏览

- 错题列表支持关键词、科目和复习状态筛选，明确空结果与加载／错误状态。
- 节点详情显示关联记录；vis-network 提供搜索、状态与关系浏览。
- 掌握等级与复习状态来自应用规则／用户记录，不视为经验证的能力等级。

验收：筛选条件与题数一致；空结果可恢复筛选；节点链接可访问；手机内容不被固定导航遮挡。

### FR-06 笔记、学习记录与复盘

- 笔记支持正文、附件、标签、编辑删除及知识关联，正式正文存 SQLite。
- AI 分类由用户触发；现有实现可能自动新增节点，这是已知局限，不写成“只推荐、不新增”。附件上传不等于全文转录或题集提取。
- 学习时长、任务与每日总结提供记录支持；复盘模型不可用时可降级为规则摘要，额度异常另行处理。
- 现有忘记／模糊／掌握／跳过使用 1／3／7／1 天间隔；不宣传为个性化记忆算法。

验收：记录可重新打开、参与相应统计；删除确认明确；规则摘要与 AI 输出可区分。时长统计不得用来证明学习效率或薄弱能力。

### FR-07 登录与数据恢复

- 页面、API、照片和导出需应用层认证；写请求检查可信来源。
- 请求大小、超时、部分并发与额度有限制。额度单位不能解释为严格费用封顶。
- 设置 JSON 导出只覆盖约定结构化数据，不包含照片本体与全部运行表。
- 完整服务器快照需联合保存一致性数据库、上传文件及 Skill 数据；配置、代码与证书另行保留。
- 生产默认禁用网页整库恢复；恢复先停写、做安全备份，在隔离环境验证再切换。

验收：未登录不能读取受保护资源；恢复失败保护原数据；数据库与附件联合校验。存在脚本不等于生产灾备已通过。

## 7. 状态与异常约定

| 用户状态 | 允许用户离页 | 反馈与后续动作 |
| --- | --- | --- |
| 本地选图／未提交 | 不保证完整恢复 | 提醒尚未服务器保存 |
| 上传中／结果不确定 | 先确认或原编号重试 | 保留输入，不重复创建 |
| 已保存／排队中 | 可以 | 显示后台状态及查看入口 |
| 整理中 | 可以 | 已识别结果可保留，个人输入不能丢 |
| 待补充 | 可以 | 指出需核对内容，允许修正或补图 |
| 整理失败 | 可以 | 显示真实失败与重试，来源仍在 |
| 整理完成 | 可以 | 解答需核对，关联与个人复盘可确认 |
| 目录候选 ready | 可以回到任务 | 明示尚未正式导入 |

“整理完成”不等于“答案正确”，“已掌握”不等于标准化能力通过，“目录识别完成”不等于已保存到知识库。

## 8. 数据、AI 与隐私边界

正式来源为 SQLite 的业务对象与持久上传／Skill 文件。关键对象包括 Subject、KnowledgeNode、MistakeItem、Note、学习与复习记录、MistakeJob、CatalogJob、WorkerLease、AiUsageDay。

原题照片、已识别题干及相关目录候选可能发送给配置的 AI 供应商。用户需在上传入口知晓该用途，避免上传个人身份或无权处理的资料。当前并未核验供应商保存期限、跨境处理或数据删除政策；这些是正式开放前的待确认事项，不虚构已落实的隐私承诺。

模型输出需结构校验、候选约束及人工校对；用户自述为用户事实，模型建议为推断。知识分类、数学解答及学习能力判断应分别评估，不能混成一个“AI准确率”。

## 10. 产品验证计划（新增建议，尚未执行）

### 10.1 应先验证什么

| 假设 | 建议方法 | 需要记录的结果 |
| --- | --- | --- |
| 保存与整理分开可减少打断 | 相同材料对照原整理方式，记录用户主动操作与等待 | 首次保存耗时、主动整理时间、离页恢复情况 |
| 记录日后更容易找回 | 若干天后给出按知识点找题任务 | 找回成功、耗时、误入路径与失败原因 |
| 用户会校对和补充个人思考 | 观察真实记录而非口头偏好 | 校对次数、卡点保存、后续回看行为 |
| AI 输出足以辅助使用 | 用有参考解答的授权样题人工评审 | 转录、解答、关联分别统计 |

建议先做作者自测基线，再邀请少量目标学习者完成探索性任务。样本数、招募方式和周期待实施前确定；小样本结果不外推整体人群。首轮先建立基线，再决定目标值，不倒填“提升XX%”。

### 10.2 指标口径

- 保存成功率：服务端已确认持久保存的唯一记录数／实际提交保存的唯一记录数；重试按原编号去重。
- 整理成功率：无需补充且生成完整整理结果的任务数／启动整理的任务数；另列待补充、失败和人工取消，不隐藏困难样本。
- 主动整理时间：用户用于选择、校对、关联和补充内容的操作时间；与后台等待时间分开。
- 找回成功率：在预先约定任务下找到目标记录的任务数／找回任务总数。
- 复习使用：一段时间内有再次打开并完成明确复习动作的记录数／到期可复习记录数；仅打开不等于掌握。
- AI 题干转录、解答与关联分别由人工基准评估；说明样题范围、难度、版本与失败样本。

### 10.3 埋点建议（未实现承诺）

建议事件：capture_submit、capture_saved、capture_failed、organize_completed、organize_failed、reflection_saved、catalog_confirmed、review_completed。仅记录必要的事件时间、版本、匿名记录标识、状态与失败类别；不记录题目正文、照片、卡点内容或密钥。实施前确认采集目的与权限，并核对现有实现，不能将本表当成已有埋点。
