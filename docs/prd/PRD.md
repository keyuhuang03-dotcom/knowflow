## 1. 产品定位与目标

KnowFlow 帮助学习者把散落的题目照片、课堂笔记和练习资料整理成能够再次找到、核对和使用的学习记录，并将这些内容连接到知识点。

核心路径：**保存材料 → AI 辅助整理 → 用户校对并补充自己的理解 → 关联知识点 → 再次查找与练习。** 内置知识骨架让使用者不必先录入教材目录才能开始；旧教材与历史内容继续保留。

当前目标：

1. 遇到错题或需要记录笔记时，先可靠保存原材料，不强迫等待 AI 完成。
2. 用知识点链接连接多份材料，使知识库可以用于查找和回看，而不只是展示目录。
3. 明确区分 AI 建议、用户确认与学习进度，避免把自动推断当作个人事实。
4. 允许把资料中的已有题目整理为在线练习，并将需要回看的作答收进错题。
5. 保留独立正文、附件和必要个人状态，为备份与未来迁移提供基础。

“减少整理负担、提高后续使用率”是价值目标，尚不是经过研究证明的效果。不承诺提分或自动评估掌握程度。[核心问题定义草稿](KnowFlow-核心问题定义-待确认.md)继续独立承载待验证假设。

## 2. 用户与使用场景

| 场景 | 用户动机 | 最小完成结果 |
| --- | --- | --- |
| 做题遇阻 | 先留下原题，稍后理解和复习 | 原照片、错题记录与任务已保存 |
| 上课或整理笔记 | 保存自己的记录并找到所属知识点 | 一篇独立笔记关联一个或多个知识点 |
| 回顾某个概念 | 查看它和其他概念的关系，找回学习材料 | 从知识点进入关联笔记或错题 |
| 使用 PDF/图片练习 | 将现有练习资料变成可逐题作答的题集 | 校对后的题集可作答、核对和收入错题 |
| 安排与记录学习 | 记录学了什么、花了多久、是否需要回看 | 保存进度、学习记录或复习事件；不等于掌握评价 |

现阶段是个人应用；不包含班级、教师管理、多人共享、机构题库及公开账户隔离。

## 3. 信息架构与入口

| 入口 | 主要用途 | 对应页面 |
| --- | --- | --- |
| 首页 | 拍下错题、查看最近录入状态与学习概览 | `/` |
| 知识库 | 按学科浏览；数学高数进入极限图谱 | `/knowledge`、`/knowledge/math` |
| 练习 | 上传资料、校对题集、在线作答 | `/practice` |
| 笔记 | 上传课堂记录、校对并查看 MD 笔记 | `/notes` |
| 我的错题 | 搜索、筛选、查看并复习错题 | `/wrong-questions` |
| 学习记录 | 记录科目与学习时长，回看历史 | `/study-tracker` |
| 设置 | 基本资料、退出及原有数据导入导出入口 | `/settings` |

手机底部为“首页／知识库／练习／笔记”；“笔记”不是错题录入的另一个入口。桌面保留错题、学习记录、设置等入口。旧任务、每日复盘、数据分析页面继续兼容，不等于已实现未来的全局薄弱点分析。

教材录入退出首页主入口；数学页的历史教材目录仍可访问。原 `/pilot` 地址重定向到数学知识页，不另建一套产品主导航。

## 4. 功能需求

### F01 首页与录入状态

首页提供拍错题入口，展示最近录入任务及真实处理状态。用户应能区分“保存成功”和“AI 整理完成”，离开页面后任务由后台继续处理。

当前首页概览仍读取旧知识节点及学习时长模型，存在“已掌握”旧文案；它不能作为新图谱学习进度或掌握率的统一统计。该差异列入缺口，不在文档中假定已统一。

验收：创建错题后能从状态入口找回；失败显示可恢复状态；导航激活项与实际页面一致，不出现多个入口都伪装成同一个录入页。

### F02 知识骨架与网状图谱

- 数学一高数极限使用 7 个参考节点、14 条真实关系，默认全部展示。不能把演示样板的 21 个节点当成已校对内容。
- 区分章节归属、前置知识、相关概念；只对有方向的关系表达方向，相关概念不强加方向。筛选控件与实际显示一致。
- 保留 Reagraph 二维网状布局，不改成树、层级、固定行列或圆周。允许合理交叉，不能为了美观删除或默认隐藏真实关系。
- 点击节点或详情关联入口，同步更新当前节点、直接邻居、连线和详情；点选不重新排布或大幅移动视角。
- 支持缩放、拖动、复位、材料展开与帮助说明。相关材料按需要展开，避免默认把所有个人内容铺满画布。
- 详情展示内置参考说明、来源/校对状态、关联知识和材料。来源链接可访问性与内容校对是不同事项，不能把外链成功当成知识准确性证明。
- 内置结构当前只读。数学各部分、408 各部分保持隔离，不能把尚未建设的章节表现成完整骨架。

验收：同数据和选中状态下检查桌面 1440/1024px、手机 390/430px；默认 14 条边，切换焦点只改变高亮和详情；20–30 节点密集测试另列，不以 7 节点可读代替。

### F03 课堂笔记

提供两类已有录入方式：知识页手工创建 MD 笔记；笔记页上传照片/PDF，由 AI 转录后校对确认。二者最终都是独立笔记，可引用多个知识点，无需复制多份正文。

上传流程：选择文件 → 文件上传及任务创建 → 后台转录 → 待校对 → 修改标题/正文、选择知识点 → 确认保存 → 查看笔记或从知识点找回。

AI 只推荐已有知识点，不虚构用户经历；未匹配可以留空。已确认笔记以 MD 为正文来源，数据库保留识别候选不能继续充当另一份可编辑正文。旧笔记通过“查看历史笔记”访问，不自动迁移或删除。

验收：同一笔记关联多个点后，两处都能找回同一内容；后台轮询不替换正在输入的校对内容；重复确认不产生多篇笔记。

当前缺口：资料校对界面的未确认修改未持久自动保存，刷新可能丢失。知识页 MD 编辑器已有页签草稿机制，两者不能混为一谈。

### F04 错题保存、整理与复习

- 支持多页照片、旋转、排序、裁剪、上传重试及已有草稿机制；先保存原图、记录和持久任务，再后台处理。
- AI 识别题干、生成标准解答并推荐已有知识点；用户核对题干/解答，填写卡点、确认或修改错因及关联。
- 卡点、错因可留空；AI 推测不能自动转成已确认的个人事实。旧 Skill 诊断保留为兼容能力，不是保存必经步骤。
- 保存个人复盘和记录复习结果，不应再次触发无必要的题目识别；后台完成或重试不能覆盖用户已经填写的内容。
- 新 MD 错题从旧列表打开时进入对应内容详情；历史错题仍使用兼容路径。

验收重点：上传完成后立即填写卡点，后台随后完成，个人内容仍保留；用户修改题干或解答后旧任务结果不得静默覆盖；重复保存和重试不制造重复记录；来源照片始终可找回。

### F05 资料练习

支持图片与 PDF 资料；当前不是“任意附件识别”。资料文件先保存，AI 只提取原有题目、选项、明确给出的原答案/解析及页码，不创作新题，不把学生手写作答当标准答案。

流程：上传 → 后台识别 → 校对题目/选项/答案/知识点，必要时移除题目 → 确认题集 → 逐题作答 → 核对或自评 → 可收入错题。

- 有明确原答案的单选题自动判定；没有答案或非单选题使用自评，不宣称自动判断推导是否正确。
- 缺少源答案时保持空白，不补猜。题目来源页码必须与实际资料相符。
- 当前 PDF 最多 12 页；文件体积、图片数量及识别结果长度有上限。失败保留原文件，提示分批或重试。
- 收入错题保留原题、原答案（若有）、用户作答、来源附件和知识关联；个人卡点仍由用户填写。

验收：缺答案不会被自动判错；收入错题操作幂等；题集确认前不能作为正式练习使用；服务重启可恢复未完成任务。

当前限制：无完整练习历史页面、自动续做与确认后题集编辑；作答虽已持久保存，不能据此宣称这些界面已完成。

### F06 链接、正文编辑与反向引用

每份内容有稳定编号，标题变化不改变身份。编辑时搜索内容并插入带路径的双括号链接；同名内容须明确目标，不靠标题猜测。A 引用 B 后，B 的反向链接由索引产生，不要求用户手写第二次。

知识点页聚合相关笔记/错题，不复制所有正文。附件使用独立文件引用。用户保存带版本校验；冲突保留候选并要求核对，首版不做复杂逐句合并。

验收：一篇笔记引用两个知识点，都能反向找到该笔记；改标题后编号不变；旧版本保存被拒绝且不覆盖新内容；重建索引不丢个人状态。外部任意移动/删除与 Obsidian 实时同步尚未支持。

### F07 学习状态与兼容功能

新知识页进度仅“未学／学习中／已学”，由用户修改；颜色不能暗示未经评估的掌握程度。复习事件与进度分别记录，新增错题数量不直接改变进度。

旧学习时长、任务和每日复盘继续存在。旧首页“已掌握”、旧分析页“薄弱科目/最高效率时段”来自旧状态或时长统计，不能作为学习能力证据；更不能冒充跨题目的薄弱点分析。

验收：修改进度再打开仍一致，复习记录可保存；导出与恢复不擅自推断进度。跨新旧模块的统计口径统一仍待处理。

### F08 备份与恢复

| 用户持有什么 | 可恢复 | 不可据此宣称恢复 |
| --- | --- | --- |
| MD＋附件（知识包信息齐全） | 正文、文件中的关系及可重建内容索引 | 学习状态、任务、候选、练习集和作答 |
| 上述内容＋学习状态 JSON | 额外恢复快照对应的知识进度及复习事件 | 所有运行数据和练习历史 |
| 完整一致性备份 | 同一快照的正文、附件、SQLite 状态、题集/作答、任务与候选 | 程序、密钥、证书、运行依赖 |

状态 JSON 是导出快照，不是另一正式编辑来源。恢复在新隔离目录进行，验证完整性、附件及关联后再决定切换。设置页原有 JSON 导入导出不能被统称为包含 vault/附件的新完整备份。

验收：恢复副本能打开相同材料、看到对应状态与作答；运行中任务按规则恢复而非全部重新生成；失败恢复不得覆盖原数据。

## 5. 状态与异常交互

资料队列现有状态为 queued（等待）、running（整理中）、ready（待校对）、confirmed（已确认）、failed（失败）。这里的状态名属于资料模块，不强行替换旧错题/目录队列状态。

- 单个文件上传成功，不等于整条记录和任务已保存；完成任务创建后才能提示可安全离开。
- AI 不可用、超时或结果不合法：保留来源，显示失败，允许按规则重试。
- 识别结果不确定：展示候选供校对，不能伪装成用户确认。
- 保存冲突：保留用户输入和 AI 候选，明确需要核对，不静默“以最后一次覆盖”。
- 数据为空：解释当前缺少什么，提供实际可用入口，不填演示记录伪装真实学习状态。

## 6. 内容与数据规则

知识点/新笔记/新错题正文以 MD 为准；历史内容仍使用原有存储，未批量迁移。附件独立保存。SQLite 同时包含可重建索引与不可丢失的个人/运行数据，不能整个当缓存清空。

练习题集目前保存在 SQLite，与笔记/错题 MD 正文不同。要实现未来跨端迁移，需要另定可移植题集与作答格式；本版不虚构该格式已实现。

知识包记录出处、范围、版本及校对状态；采用“内置参考说明”，不滥用“官方定义”。数学一范围尚未逐条对照指定年份考试大纲；扩展前需要内容复核。

## 7. 视觉、质量与安全约束

- 网站保持奶白、青柠绿、手绘元素及现有卡片风格；图谱局部为纯白画布、浅色赛博节点、清晰轻细连线。
- 点击目标、表单、帮助说明在手机可使用；不能以大幅缩小字号换取空间。
- 登录、附件访问、来源校验、请求大小、模型额度和后台租约继续复用现有保护。
- 写入验收使用隔离数据。浏览器模拟尺寸不等于 iPhone Safari 真机；模拟 AI 不等于真实识别质量。
- 不因本地构建通过而认定视觉、恢复、内容准确性或线上部署通过。

## 8. 当前缺口与后续范围

| 项目 | 当前事实 | 后续处理建议 |
| --- | --- | --- |
| 统计语义 | 旧首页/分析存在掌握、效率与薄弱标签 | 先统一为可解释的记录统计，不替代能力评估 |
| 校对草稿 | 资料页刷新可丢未确认修改 | 优先补恢复与离页保护 |
| 练习记录 | 作答已保存，历史/续做界面未完整 | 补找回与继续练习流程 |
| 备份入口 | 设置旧 JSON 与新完整备份并存 | 明确命名及覆盖范围后再统一入口 |
| 内容覆盖 | 极限局部参考包 | 人工校对后分章节扩充 |
| 模型与图谱质量 | 有简单样本及小图验证证据 | 中文手写、复杂 PDF、密集区域和真机继续验收 |
| 启用条件 | 新内容服务需要隔离启动配置 | 发布时统一启用策略，不让可见入口指向不可用服务 |

以下明确后置：用户主动发起的全局薄弱点分析、完整高数骨架、历史批量迁移、多端同步、App、多人平台。已有每日复盘不视为全局薄弱点分析已交付。

## 9. 验收记录与产品评估

每次验收记录日期、数据范围、设备/视口、操作步骤、预期/实际结果与证据。主流程至少覆盖：知识点找回材料、拍照错题与用户并发填写、笔记多知识点关联、练习缺答案自评、任务失败恢复、完整备份隔离恢复。

建议后续观察保存完成率、主动校对时间、AI 等待与失败原因、数天后能否找到并独立重做。尚无统一基线或目标数值，不能编造“提升效率百分比”；研究结果支持或反驳价值假设都应保留。

本版完成的是需求与现状对齐，不是新增功能发布。具体实现索引见 [架构](../architecture.md)，运行与验证方法见 [开发说明](../development.md)。

## 10. 既有交互保护规则

保留多页错题及教材录入、直接拖边裁剪、旋转和排序；未应用的裁剪先应用或重置后再切页。数学公式覆盖标题、选项、摘要和提示，不只渲染正文。复习卡片的方法、步骤、答案分层，不堆叠重复的诊断提示。

历史目录须忠于上传内容，按章/节/小标题展开，页码清晰显示；确认保存前不显示已归档，缺失书名等信息有明确反馈。数学各部分与 408 各部分不混用推荐节点；不把旧演示内容冒充上传教材。以上兼容规则不恢复已经撤下的首页录目录入口，也不改变当前四项手机导航。
