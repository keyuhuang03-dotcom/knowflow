## 1. 背景与问题定义

考研学习材料分散在教材、题目照片、课堂笔记和个人批注中。保存一道错题通常还需要摘录题干、寻找解答、判断对应知识点、补充自己的卡点，并在之后重新找到它。KnowFlow 一期围绕这条记录与回看流程提供集中工作台。

项目的价值假设是：降低形成可复习记录的额外成本，让错题能与教材知识点、笔记建立联系。它不是已被用户研究证明的普遍结论，也不能据此声称提高成绩或学习效率。当前 [核心问题定义草稿](KnowFlow-核心问题定义-待确认.md) 用于后续研究，不属于已完成的访谈成果。

一期目标：

1. 先保存照片和错题，用户不必等待 AI 完整分析才能离开。
2. 依据个人教材建立分科、分部分的知识目录，关联错题与笔记。
3. AI 提供题干整理、标准解答和关联建议，用户保留卡点与错因的判断权。
4. 通过错题列表、知识节点及复习入口重新找到记录。
5. 在识别失败、页面关闭或后台中断时保留来源和任务，支持恢复。

不以“功能数量最多”为目标；一期取舍重点是照片保存、后台整理、目录确认与用户复盘的闭环。

## 2. 用户与核心场景

目标使用场景是个人考研学习；当前单人部署不等于已经支持公开注册或多人隔离。

| 场景 | 当前困难假设 | 一期提供的结果 |
| --- | --- | --- |
| 做错题但需要继续学习 | 手动整理打断节奏，担心资料遗失 | 多页照片先保存，后台整理并显示状态 |
| 更换或补充教材 | 学科范围相同，但目录、章节和页码不同 | 拍目录、校对层级与页码、确认追加或替换 |
| 回看一类问题 | 照片缺少知识归属和个人复盘线索 | 关联已有知识点，保存用户卡点和错因 |
| 整理笔记 | 正文、附件与知识点分散 | 独立笔记、附件引用、标签和知识关联 |
| 日常复习 | 不清楚哪些记录需要回看 | 复习队列、状态记录、学习时长和任务支持 |

这些场景用于解释产品设计，并不代表已经完成规模化访谈。真实用户规模、留存、节省时间和提分效果目前没有可引用的统计结果。

## 3. 一期范围与信息架构

| 模块 | 用户入口与职责 | 范围 |
| --- | --- | --- |
| 首页 | 拍下错题、录入教材目录、最近录入状态与概览 | 核心 |
| 我的知识库 | 学科、教材分区、章/节/小标题、知识节点详情 | 核心 |
| 我的错题 | 添加、查询筛选、查看解答、补充卡点与复习 | 核心 |
| 知识图谱 | 原有节点与关系可视化，节点详情和关联材料 | 辅助；一期使用 vis-network，不是 Reagraph |
| 笔记 | 手工正文、附件、标签、AI 分类及知识关联 | 辅助；正文存 SQLite |
| 学习记录与任务 | 学科时长、最近记录、任务完成情况 | 辅助 |
| 每日复盘与数据分析 | 当日数据总结、近 30 天学习记录统计 | 辅助；不是全局能力诊断 |
| 设置与数据保护 | 个人配置、退出、结构化导出及恢复边界 | 基础保障 |

手机底部导航实际为 **首页／知识库／拍照／记录**：“拍照”进入错题录入，“记录”进入错题列表。它不是二期的“练习／笔记”导航。桌面主导航保留首页、知识库、错题、学习记录及设置；已有其他功能页面不应被写成全部都是一级导航。

数学区分高等数学、线性代数、概率论与数理统计；408 区分数据结构、组成原理、操作系统、计算机网络；英语、政治独立。这里是教材和节点的分区能力，不代表内置完整全科知识库。

## 4. 核心流程与功能规则

### F01 错题照片保存

流程：选择相册或连续拍照 → 多页预览 → 裁剪/旋转/排序 → 上传 → 保存错题与持久任务 → 返回记录查看后台状态。

- 默认每批最多 6 页，支持 JPG/PNG/WebP；HEIC 需转换或使用兼容相机格式。
- 裁剪直接拖动四边/四角，不使用百分比滑条。未应用裁剪应先应用或重置，再切页或上传。
- 客户端压缩最长边到 2400px；保留已有浏览器草稿与上传重试机制，但浏览器清理存储或解码中断不保证草稿完整恢复。
- 全部来源及记录/任务创建成功后，才可告知用户保存完成。单张文件上传成功不等于整条错题保存完成。
- 重复提交用稳定记录编号收敛，不能因响应丢失而复制多条错题。

验收标准：多页顺序正确；失败可重试；离开页面后已保存任务继续处理；AI 不可用不删除照片。仅对测试副本执行写入验收。

### F02 AI 整理与用户复盘

流程：Worker 领取任务 → 识别题干 → 生成标准解答/答案/方法 → 推荐已有知识点 → 用户校对并填写卡点、确认错因和关联。

- 题干识别与解答分开；识别检查点用于后续恢复，不把每次重试都变成从头识别。
- 不要求模型先看懂学生手写错误才能保存或给解答。模型可给中性自查建议，不能将猜测当作用户实际错因。
- 用户可以自行填写卡点、多选或自填错因，也可以留空。
- “保存错因”“保存补充”“完成复习”等入口应一起保存当前个人内容；后台完成或人工校对不得整体覆盖 `selfReport`。
- 题干、标题、选项、摘要和解答均支持公式渲染；方法、步骤、答案分层，避免重复堆叠诊断提示。
- 旧 Skill 诊断、修订和 Word 导出保留兼容，不是新错题保存必经步骤。

验收标准：用户在后台处理时补充卡点，任务完成后内容仍在；旧版本结果不能覆盖新输入；失败后原题、已识别内容及个人复盘可找回。模型答案仍需用户核对，不宣称数学解答准确率已达某一数值。

### F03 教材目录与知识库

流程：选择学科和部分 → 上传多页目录 → 后台逐页识别 → 查看页级进度与候选 → 校对书名/标题/页码/父子关系 → 确认追加或替换 → 浏览目录和节点。

- 数学与 408 各部分独立，不能跨分区混用教材和推荐节点。
- 保存来源与中间进度；后续页失败可恢复已完成页，不强迫重录整份目录。
- `ready` 只表示候选可预览；用户确认导入后才是已保存，不能把识别完成当归档完成。
- 总览先展示章，展开显示节和小标题；页码直接展示“第 N 页”。
- 替换教材目录归档旧节点，不能连带删除旧错题、笔记与关联。
- 缺书名或关键字段时明确反馈，保存成功后应可回到对应分区找到结果。

验收标准：多页目录顺序与归属正确；中断可恢复；确认前不污染正式目录；替换后历史关联仍可访问。模型输出只是候选，不保证识别目录天然正确。

### F04 找回记录与知识图谱

错题列表支持关键词、科目和复习状态筛选；节点详情可连接相关错题、笔记与知识关系。原有图谱使用 vis-network，并支持节点状态、搜索及详情等交互，不应把二期极限演示图写成一期界面。

一期已有 `masteryLevel` 0–5 和未学习/学习中/已掌握/重点知识/高频错题等状态表达。这是应用记录机制，不是标准化能力测评。二期“仅显示学习进度”的方向不能倒写成一期已经采用。

验收标准：筛选结果与题数一致；手机搜索和筛选不遮挡；节点关联能定位到对应记录；切换页面的高亮正确。图谱服务于浏览和找回，不构成 AI 诊断证据。

### F05 笔记与附件

一期笔记支持新建、编辑、删除、标题/正文/标签、上传附件及知识关联。附件以链接或图片语法写入正文，正文仍保存在 SQLite 的 Note.content 中，不是独立 MD 文件。

用户可主动发起 AI 分类；按标题与正文请求分类并返回知识匹配。一期分类接口还会根据模型建议创建知识点，因此不能宣传为“所有 AI 入口都只推荐现有节点、绝不新增”。这是当前设计局限，后续需增加候选确认与范围约束。

附件上传不等于已实现拍照笔记全文 OCR 或 PDF 自动题集。二期才计划重构为原材料先存、后台转录、用户确认的独立笔记流程。

验收标准：保存后可重新打开；附件链接保留；知识关联可找回；删除有明确确认。AI 分类质量及自动新增策略需单独评估。

### F06 学习记录、复习与每日总结

- 学习记录保存科目、时间与分钟数；任务记录标题、优先级及完成状态。
- 知识复习根据用户选择安排下次时间：忘记/模糊/掌握/跳过分别使用现有 1/3/7/1 天间隔；掌握等级在 0–5 内增减，跳过不算一次实际复习。
- 每日复盘读取当日学习时长、任务、错题和复习节点，生成总结、优点、问题与建议；文本 AI 不可用时有基于记录的规则摘要降级，额度错误另行处理。
- 数据分析展示近 30 天时长等统计。一期页面把记录较集中时段称为“最高效率时段”、较少学习时长科目称为“薄弱科目”，这些名称超出了数据可证明的范围。

验收标准：保存的学习记录参与统计，复习结果更新对应节点，重复生成同日复盘更新已有记录。复盘生成、规则降级与能力评估不是同一件事；不将“有分析页”写成已完成全局薄弱点诊断。

### F07 登录、后台与备份

- 页面、API、照片和导出具有应用层登录保护；请求来源、请求体、并发、超时与 AI 调用额度有限制。
- Web 和独立 Worker 共用持久 SQLite 与文件目录；租约、版本检查和有限重试处理中断与重复消费风险。
- 设置导出为结构化 JSON，包含相关业务记录与关系，但文件路径不等于文件内容；它不是包含全部照片和运行表的完整灾备包。
- 服务器完整备份覆盖 SQLite、上传文件及 Skill 数据；程序、私有配置和证书恢复范围需分别核对。
- 生产默认关闭网页整库恢复；离线恢复先停写、做安全快照，在隔离环境验证后再切换。

验收标准：未登录不能读取受保护资源；识别失败不丢来源；备份传输完成后再校验；不以存在备份脚本就声称已经完成生产灾备演练。

## 5. 重要异常和状态反馈

| 情况 | 用户应看到/保留的内容 | 一期处理原则 |
| --- | --- | --- |
| 上传失败 | 原输入和可重试入口 | 不伪报保存成功，不重复造记录 |
| 等待/处理中 | 真实后台状态 | 页面关闭不承担执行或取消任务的职责 |
| AI 超时或不可用 | 原照片、已保存记录、错误与重试 | 有限重试、恢复检查点，不无期限等待 |
| 目录识别完成 | 待核对预览 | 未确认前不显示已正式保存 |
| 后台结果晚到 | 最新用户卡点和输入 | 校验任务版本，保护个人复盘 |
| 数据/模型不足 | 可核对候选或明确失败 | 不补造学生事实，不把流畅回答当正确证明 |

资料练习队列的 `confirmed` 等状态属于二期，本版不混入一期状态模型。

## 6. 数据与非功能要求

一期正式来源是 SQLite 业务记录与独立上传/Skill 文件。主要对象为学科、章节、知识节点、错题、笔记、学习记录、任务、每日复盘和后台任务；正文并非统一由 MD 文件提供。

优先保证保存、可恢复和用户内容保护，再优化识别耗时。手机以拍照/状态查询为主，桌面承担目录整理和回看；奶白、青柠绿、手绘及玻璃卡片风格保持一致。所有验证使用隔离数据，生产浏览器默认只读。

单人部署、数据库模型及代码测试不能证明多人安全、真机兼容或高并发承载能力；没有进行的测试不填“已通过”。

## 7. 一期迭代与项目管理复盘

以下根据既有记录回溯整理，不伪造完整排期、人天或团队分工。

| 发现的问题 | 已交付调整 | 管理/验收关注点 |
| --- | --- | --- |
| 保存依赖完整 AI 响应，离页或失败容易失去进度 | 照片/记录先落地，独立后台任务、有限重试与恢复 | 将“保存成功”与“整理完成”分开验收 |
| 教材多页识别等待长，中间结果不持久 | 分页后台处理、检查点、预览与确认导入分离 | 恢复失败页、保留历史节点、明确保存状态 |
| 用户点保存补充后错因未完整保存 | 统一复盘草稿与保存入口 | 不按按钮数量验收，按完整用户意图回归 |
| 图片处理和手机布局影响使用 | 直接拖边裁剪、多页/旋转、紧凑录入与导航、筛选栏对齐 | 手机和桌面对照，确认没有破坏原布局 |
| 发布可能覆盖数据或造成不可恢复故障 | 增量迁移、快照、校验、旧版本与镜像保留 | 代码发布、数据保护及业务验收分别检查 |

可用于面试说明的重点是问题识别、范围取舍、需求拆解、验收及迭代闭环，而不是把二期想法凑进一期功能数量。

## 8. 交付证据、成果与限制

一期已交付 Web 应用并上线，这是用户确认及既有发布记录支持的项目成果。2026-10-26 记录包含 40 项单元/隔离集成测试、类型检查与构建，以及手机/桌面与筛选交互验证；这不是本次重跑，也不是 AI 识别准确率。

证据位置：源码基线 `f8f761e`；本机 `data/deployment/20261026-filter/result.md` 及同目录真实截图；其他发布、裁剪、目录与复盘证据位于 `data/deployment/`。这些私有证据不直接提交个人数据到仓库。

尚未有可引用结论：真实用户数、活跃/留存、人工整理耗时降低比例、题干/解答准确率、提分效果、Safari 全流程真机和生产全量灾备验收。

后续评估可记录保存完成率、等待与失败原因、校对主动操作时间、数天后找回与重做情况。先建立基线，再设目标，不反向编造一期结果。

## 9. 简历与作品集使用边界

可以据实展示：已上线的个人学习工作台；教材/错题/笔记关联；多页拍照与后台整理；用户自填卡点；需求迭代、验收及上线保护。具体个人职责应由本人核对后填写，不自动宣称带领团队、完成用户访谈或独立承担所有实现。

一期存在的自动分类新增节点、时长统计被称为薄弱/效率、重复入口等局限可作为复盘，不在材料中隐藏，也不宣称已经修复。当前重写 PRD 是项目成果整理的一部分，不是项目起始时已形成的证据。
