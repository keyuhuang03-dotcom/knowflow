# KnowFlow 核心问题定义

日期：2026-11-13 · 状态：草稿

## 1. 核心问题

**核心问题：考研学生遇到错题后，难以用较低的额外投入，留下可供下一次做题使用的个人复习线索。**

当前问题假设包含两个潜在断点：“整理费时间”影响持续记录，“整理后不会复习”影响记录的实际价值。“找不到”属于复习阶段的候选障碍，需先确认其发生频率与影响，再确定检索和导航的改进优先级。

验证重点：通过连续使用记录和目标用户操作观察，确定录入、理解、查找、重做四个环节中的主要阻力。以上为待验证的问题定义，尚未形成用户研究结论。

## 2. 用户与场景

**目标用户：** 正在备考、经常使用纸质教材和习题、会保存错题的学生。首轮聚焦数学与 408 场景，以项目发起人的连续使用记录作为初始个案，再通过其他目标用户验证问题的共性。

**核心场景：** 学生做错一道题或对照答案后仍有疑问。此时希望继续学习，又担心下次遇到同类题仍然卡住。几天后复习或再次遇题，需要找到原题，并理解“上次卡在哪里、什么条件下用什么方法、这次应检查什么”。

**核心流程：** 做题遇阻 → 保存原题 → 看懂解答 → 留下自己的卡点与提醒 → 再次找到 → 独立重做 → 更新理解。

## 3. 现有办法与可能不足

现有替代方案及其潜在不足如下，实际使用情况与问题程度需通过访谈和操作观察确认。

| 现有办法 | 能解决什么 | 待核对的不足 |
| --- | --- | --- |
| 纸质错题本、教材批注 | 保留原题位置和个人思路 | 抄题是否耗时；跨书查找是否困难 |
| 手机照片、相册或聊天收藏 | 快速留下题目 | 是否缺少上下文、分类和回看习惯 |
| 笔记软件、表格 | 集中整理、标签与检索 | 是否因维护成本中断；是否只收藏答案 |
| 答案解析、AI 问答 | 帮助理解当次题目 | 当次看懂后，是否留下个人卡点并再次重做 |

## 4. KnowFlow 的价值假设与边界

KnowFlow 目前已经支持照片先保存、后台生成解答卡片、关联教材知识点，以及用户自填卡点／错因和记录复习状态。**价值假设：降低形成可复习记录的成本，提高错题记录在后续复习中的可用性。** 验证分为两部分：AI 识别与解答的质量，以及用户能否借助记录完成回看和独立重做。

**阶段范围：** 覆盖“保存一道错题，到之后独立重做”的流程，重点关注录入、整理和再次使用。全科智能教学、自动诊断个人能力、公开多人平台和 Obsidian 双向同步暂不纳入这一阶段。是否提高学习效率，需要后续数据支持。

## 5. 待验证假设与判断方法

| 假设 | 如何验证 | 什么结果会改变判断 |
| --- | --- | --- |
| H1：额外整理成本阻碍持续记录 | 请参与者展示最近一次真实错题，用原有方式整理，记录操作、耗时和放弃原因 | 若主要障碍是看不懂解答，应优先解决理解支持 |
| H2：现有记录缺少个人复习线索 | 让参与者回看几天前保存的题，说明当时卡点、方法条件和本次检查点 | 若记录充分但无法找到，应转向定位与检索 |
| H3：KnowFlow 降低有效整理成本 | 同一参与者分别用现有方式和 KnowFlow 处理难度相近的题，计入 AI 等待、校对和修改时间 | 若校对成本抵消节省时间，应先改善模型质量或录入流程 |
| H4：形成卡片后会再次使用 | 数天后观察能否找到记录、先独立重做，再核对卡片；询问使用或未使用原因 | 若只上传、不回看，应重新判断复习动机与使用时机 |

## 6. 首轮验证与决策

**验证计划：** 先开展项目发起人的连续使用记录，再邀请 5–8 名目标用户进行探索性测试。经参与者同意后收集题目和操作记录，观察整理主动操作时间、AI 等待时间、人工修改时间、复习线索完整性，以及后续查找与独立重做情况。首轮样本用于发现问题，不用于推断整体用户比例或提分效果。

**决策依据：** 首轮验证需回答：**主要阻力发生在录入、理解、查找还是重做？下一版只优先解决哪一个？** 若整理成本最突出，优先简化录入和校对；若查找最突出，优先改善定位；若回看却仍不会做，优先验证卡片内容与重做流程。改进目标在取得原有方式的基线后设定；验证记录需同时保留支持和不支持原假设的结果。
